结论：暂不通过上板验收。现有测试通过且独立完整构建成功，但存在以下实际控制和集成缺陷。本次只审查，未修改生产代码，未操作硬件。

- 现有真实任务测试将 `boot_ui_manual_run/active/take_record_request/ack` 全部替换为空桩，因此没有覆盖引导页面与真实 Ctrl 的集成。

## 1. [P1] 结果窗口开始时，控制任务尚不读取手柄

位置：`Core/Src/freertos.c:384-391`；`Core/Src/boot_ui.c:685-693,861-887,583`。

`boot_ui_ready` 只有 `ui_main_page` 设置。结果窗口在进入主页面前执行，Ctrl 因 ready=0 一直跳过读取。UI 使用的 `home.frame_valid` 因此一直为零，`manual_ref_step` 不处理 USER，五秒内按键无法进手动页。

修复：明确自检后移交阶段，使 PS2 在结果窗口/手动页可读取，但普通驾驶始终禁止。不要仅提前置 ready，让摇杆直接驱动。

新增测试：运行真实启动流程，确认结果窗口内能够按 USER 进入手动页，同时摇杆全行程也不能产生非零 PWM。不得替换掉这几个真实接口。

## 2. [P1] 一次超过 50 ms 的采样间隔会永久拒绝后续样本

位置：`Core/Src/wheel_home.c:472-501`；`Core/Src/freertos.c:393-411`。

超时后 `last_position_ms` 没有推进，也没有重新初始化反馈实例。后续循环时间与旧时间差一直大于 50 ms，永远走失败分支。Ctrl 首次先采样再执行约 120 ms 的 `ps2_config`，正常启动就能触发此问题。长按记录与归位因此可能永久不可用。

修复：初始化链路与首个有效采样时机一致。发生真实超时后停止运动、使旧参考失效、以当前 CNT 重建 Ctrl 私有跟踪器，再允许新鲜样本和重新记录。不能保留可能漏回绕的旧参考。

新增测试：真实配置耗时 120 ms 的启动；一次 60 ms 调度停顿后，每 10 ms 继续采样，确认旧参考失效但可重新记录和归位。

## 3. [P1] 自检失败没有成为禁止驱动的故障

位置：`Core/Src/freertos.c:491-535`；`Core/Src/motor_health.c:24-32`；`Core/Src/boot_ui.c:843-855`。

健康检测初始化故障为零。自检失败时调用 `clear_after_selfcheck(false)` 仅不清故障，不会将自检失败锁存为故障。因此初次开机 B 自检失败后仍可进入手动驱动。运行监测可能在稍后停机，但这不能替代自检失败立即禁止输出。

修复：把逐轮自检失败/跳过状态传入控制仲裁，禁止非零输出；保留原因。只有主动重新自检全部通过才能清除，并提供实际可调用的重新自检流程。

新增测试：以四轮自检结果含一轮 FAIL 启动真实 Ctrl，立即给有效非零摇杆，断言四路 PWM 一直为零；SELECT 记录不得清除故障。

## 4. [P1] 失联重连后可能直接执行偏置摇杆

位置：`Core/Src/wheel_home.c:552-569`；`Core/Src/freertos.c:466-473`。

失联时只有 RUNNING/BUTTON_HELD 进入等待居中，MANUAL 保持不变。`require_release` 仅阻止 SELECT，不阻止普通摇杆。重连首帧若摇杆仍偏置，Ctrl 会马上输出非零。

修复：失联后所有可驱动状态进入零输出等待；新链路确认 SELECT 释放且摇杆居中连续 100 ms 后才允许驱动。

新增测试：手动驾驶→失联→偏置摇杆重连，必须持续零输出，之后居中满 100 ms 才恢复。

## 5. [P1] 目标附近跨过容差区时绕过 40 ms 换向等待

位置：`Core/Src/wheel_home.c:302-320,339-356`。

误差进入容差时直接清除 applied_direction。下一帧若惯性带来反向误差，程序忘记刚才方向，会立即输出反向最小 PWM。可复现为正向 PWM→10 ms 容差零输出→再过 10 ms 负 PWM，没有达到规定的 40 ms 零输出。

修复：保留最后实际驱动方向和停止时间；跨容差/停稳状态也要计算距上次非零输出的时间。等待未满足前不得反向。

新增测试：穿过目标容差再漂到另一侧，而不只是从正误差直接跳到负误差。

## 6. [P2] 手动页记录请求没有实际保存参考，停稳条件也不可满足

位置：`Core/Src/freertos.c:554-559`；`Core/Src/boot_ui.c:692-700`；`Core/Src/wheel_home.c:645-648`。

Ctrl 只计算 ok 并调用 ack，没有执行四轮 origin 保存。ok 又依赖 settled_mask，但 MANUAL/BUTTON_HELD 会清零该掩码，无法把它当四轮连续停稳标志。正常 SELECT 长按分支虽独立保存 origin，页面状态与请求/应答仍不一致，可能已经记录却仍提示 HOLD SELECT。

修复：提供 Ctrl 单一“按当前有效计数记录参考”入口，检查全部四轮连续停稳和摇杆居中，成功后捕获四个 origin，并应答 UI。不要用归位完成掩码表示静止。所有轮都满足应使用全轮条件，而非 mask!=0。

新增测试：真实手动页长按 SELECT→origin 四轮被更新且 UI REF SET；任一轮仍转或摇杆偏置→不更新且不显示成功。

## 7. [P2] 窗口已释放时的第一次 USER 新按下被吞掉

位置：`Core/Src/manual_ref.c:112-116`。

`window_seeded` 初始为零，第一次按下总被当作“打开窗口时已按住”。即使 USER 已释放数秒，新按下仍只会 seed，不进入页面。现有测试先模拟 USER 一直按住再释放，漏掉正常情况。

修复：窗口打开时读取并设置真实初始电平；已观察到释放后，下一次稳定按下应进入页面。USER 是本地主板按键，不应被无线手柄有效帧阻断。

新增测试：窗口打开时 USER 释放→新按下进入；窗口打开时 USER 按住→必须释放再新按；手柄未连接时 USER 仍可进手动页。

## 8. [P2] 正常停止和运行故障没有让驱动睡眠

位置：`Core/Src/freertos.c:308-310,535-550`。

归位完成、卡轮/超时、运行故障只把命令清零，`ctrl_apply` 的零分支不清 SLP/awake。只有 CAL/失联路径真正调用 sleep，与设计的完成/故障后睡眠不符。

修复：让停止原因明确传至统一输出出口，故障/归位完成/手动对齐先 CCR=0 后清 SLP，并同步 awake 状态，后续启动仍保留零 PWM 唤醒等待。
