# 电机自检与 PS2 排查记录（2026-10-30）

## 现场结果

- 首次连接既有 OpenOCD 服务时，目标已经处于 halted 状态，TIM8 四路 CCR 均为 0。不能认定是谁或什么流程暂停了主控。
- 从 Flash 读取 65536 字节备份为 `/tmp/events-before-debug.bin`。与当时本地 42648 字节构建不一致，所以源码状态不能直接当作板上运行状态。
- 临时 SRAM 程序绕开 FreeRTOS、自检 UI 和手柄，逐个使能 A/B/C/D，PWM 1 kHz、25%，有本机超时停止。用户确认 **A、C、D 转动，B 没有动**。
- 第一次将每次编码器变化取绝对值累加，A 累计 209314、约 4855 ms，但起止计数均为 1，不能据此声称轮子实际转了一圈。这种累加会放大来回抖动，结果已作废。
- 复测改为每 1 ms 采样、16 位回绕差值累计净位移：A 净位移绝对值 1，B/C/D 为 0。每轮在约 1 s 无进一步净位移后停止。用户确认 A/C/D 确实转了，说明当前编码器反馈不能代表轮子转动。**本次没有实现或验证“各轮准确一圈”。**
- 四路编码器 TI12、通道使能、GPIO 复用读回与当前引脚表相符。这不证明编码器供电、两相信号、连接器与实际接线正常。
- TIM8 CH1~4 与 PC6~9 复用读回正确。B 的软件映射仍为 PWM=PC8、DIR=PC0、SLP/EN=PB14；B 不转的具体硬件原因尚未确认。

## 已修正的软件问题

1. 自检和失联会将 SLP 拉低，原手柄任务只写 DIR/CCR，没有重新拉高 SLP。已在首次有效非零指令前唤醒四路驱动、等待 10 ms，失联后重新进入睡眠状态。
2. PS2 原来只验证 0x5A 标记，会把 0x41 数字模式等帧中的非摇杆字节用于速度映射。现在只接受 0x73/0x79 模拟模式。
3. 接收器配置事务之间增加 20 ms 间隔。冷启动探测曾先读到全 FF，随后 0x41；再次配置后连续得到 0x73。采用实际 `ps2_gamepad.c` 驱动在板上独立运行，连续八次有效，四个摇杆均为 128、按键未按下。此结果只证明 MCU 到接收器的读取链路；无线手柄操作还需以值变化确认。
4. 原自检不读编码器，流程结束无条件显示 OK。现在每个通电方向分段采样，需要至少 32 个净计数的运动证据；卡住、无反馈、只有一个方向有反馈都会标记失败。此检查验证反馈存在，不验证转速、实际方向或完整圈数。电机结果汇总页面也使用真实结果。

## 手柄使用

当前不是 USB 手柄路径。厂家 `pstwo.h` 与当前驱动一致：PE0=DI、PE1=DO、PE2=CS、PE3=CLK。

无线手柄和配套接收器自行建立无线连接；固件通过 PS2 命令配置接收器模拟模式并轮询数据，不存在给 FreeRTOS 做无线配对的步骤。具体手柄的对码键/灯态须以型号说明为准。

当前正常固件需要按主板 KEY 启动自检；四轮电机流程已缩短到约 5.6 秒，另加界面和电压检查，通过电压检查进入转速主页面后，手柄任务才接管。它目前只使用左摇杆 Y 轴控制四轮前后，松手回中位输出为零，失联后停止并让驱动睡眠。没有 START 解锁门槛，也尚未实现转向、横移或完整厂家按键功能。旧厂家程序中的 START 操作不能直接当作新固件的操作要求。

目前 B 不动且编码器反馈异常，尚不能验证四轮正常行驶或精确圈数。优先核对 B 驱动供电/EN/电机接口，以及四路编码器供电、共地、A/B 相和接口对应；不要仅凭 OLED 电机图标判断机械状态。

## 后续正常固件复核（修正早期独立探测结论）

正常 RTOS 固件下进行摇杆运动采集，四路编码器均有连续正负净计数；一个约 120 ms 窗口记录到 +22000/-22343/-22437/+22505。此前 SRAM 独立探测的零计数结论不能继续作为编码器故障或接线损坏的依据。

逐轮手转标定进一步确认：实际右后 C 接 TIM5，实际左后 D 接 TIM4；旧 UI 的后轮反馈对应错误，已经修正。每轮的整圈参考、前进方向与后续半圈显示复核见 `wheel-feedback-calibration-2026-10-30.md`。

## B 轮恢复与快速推杆反馈

用户在恢复手柄后确认 B 能转，但方向反，快速推杆仍感觉延迟。操作后诊断为 19927 次读取、19927 有效、0 错帧、仅启动配置一次，最大间隔 14 ms（首次非零指令唤醒包含 10 ms 等待）。摇杆映射无加速缓坡，死区为中位 ±16；当前数据不能把端到端延迟归因于轮询。已请用户区分启动、回中滑行或快速换向。

按实际安装方向，B 的 PC0 前进改高电平、后退改低电平，自检与手柄共用。新增真实任务测试先复现 B 正向 PC0 低的断言失败，修正后七组测试通过。编码器方向及四轮圈数标定不改。新机械方向待用户复核。

B 方向修正版写入后读回 44132 字节与构建完全一致。跳过运动自检进入主页面，四路 PWM 为零；随后恢复手柄，居中状态待用户复测 B 机械方向。

## 接线恢复后的现场采集

用户确认接线已接牢、摇杆居中后恢复手柄，随后反馈启动响应“好多了”。约 180 秒顺序 SWD 采集捕捉到前推/后拉、B 输出和编码器响应。持续前推时 PC0=0 且 B 编码器净增，后拉时 PC0=1 且净减，支持原方向定义的双向运动链路正常。回中后最终四路 PWM 均为零。详细片段与诊断见 `ps2-startup-observation-2026-10-30.json`；顺序读取每行约 20–25 ms，不能用同一行不同寄存器的瞬态差异推导精确延迟，亦未测得无线到机械端到端时间。
