# 固件架构

主控 STM32F407VET6。HAL + FreeRTOS（CMSIS_V2）。本文件描述分层与任务模型，具体模块见各车型正式分支。

## 一、分层

```
应用层    ui_model  ui_render  selfcheck_service  wheel_home  manual_ref
业务层    drive_ctrl  motor_health  power_monitor  motor_test  buzzer
设备层    oled_gfx  oled_font  ps2_gamepad  flog  motor  encoder  adc
平台层    STM32 HAL  FreeRTOS  CMSIS
```

规则：

- 上层可调用下层。下层不反向依赖上层。
- 应用层不直接写电机，也不直接操作 GPIO。
- 设备层不包含业务判断。

## 二、任务模型

| 任务 | 周期 | 职责 |
|---|---|---|
| Ctrl | 10 ms | 输入采样、页面推进、动作仲裁、唯一电机出口、快照发布 |
| UI | 20 ms | OLED 渲染，只读快照 |

设计要点：

- **单一写入路径**：电机写入只经过 Ctrl 任务的 `ctrl_apply()`。UI 只读快照，不产生副作用。
- **快照同步**：UI 通过 seq-lock 读取一致快照，避免渲染撕裂。
- **无阻塞**：蜂鸣器、OLED 刷新均非阻塞，不占任务时间片。

## 三、安全设计

| 机制 | 行为 |
|---|---|
| 上电默认 | 不输出，四轮保持静止 |
| 自检门控 | 本次上电未通过自检，进入驾驶页也零输出 |
| 电压门控 | VDD < 3100 mV 时禁止一切运动输出 |
| 故障锁存 | 检测到反馈异常立即清零输出，需完整重跑自检才清除 |
| 手柄失联 | 200 ms 无有效帧即停机；坏帧当拍丢弃 |
| 动作取消 | 归位与自检过程中失联，当拍取消 |

## 四、纯逻辑与可测性

应用层与业务层的核心状态机写成纯 C，不引入 HAL 头文件。主机侧用 `tools/host_stubs/` 提供替身，可在 x86 上直接跑单元测试。

这条约束是主机测试可行的前提。新增模块若引入 HAL 依赖，就不能脱离硬件测试。

## 五、协议与接口

- **上位机串口**：USART1，115200 8N1，帧格式由各车型分支定义。
- **调试串口**：USART3，115200 8N1，板载 CH340。
- **蓝牙**：UART4，9600 8N1。

## 六、构建产物

`make` 输出三个文件：

| 文件 | 用途 |
|---|---|
| `.elf` | 调试与反汇编 |
| `.hex` | Intel HEX，通用烧录 |
| `.bin` | 裸二进制，`0x08000000` 起始 |

烧录使用 ST-LINK V2 + STM32CubeProgrammer。写入后必须独立读回并逐字节比对。
