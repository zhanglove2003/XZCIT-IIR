# 调试坑与解决方案（交接文档）

来源：XZCIT-MFSC 固件 2026-10-31 ~ 11-01 的实车开发全过程。每条按"现象 → 根因 → 解决"记录。新接手的人遇到同类症状先查这里。

---

## 1. 烧录与 USB

### 1.1 ST-LINK 连接间歇超时 / 擦除随机失败
- **现象**：st-flash 或 CubeProgrammer 偶发 `LIBUSB_ERROR_TIMEOUT`、`failed to erase memory`，重试偶尔成功偶尔全失败；严重时连 `GET_VERSION` 都超时。
- **根因**：USB 链路（hub / 扩展坞 / 长线）。换到电脑直连口后彻底消失。
- **解决**：直插主机口 + 短好线。出现超时雪崩时拔插 ST-LINK USB 复位它的状态。

### 1.2 NRST 未接，无法"复位下连接"
- **现象**：`Can not connect to target. Please use 'connect under reset'`，加 `--connect-under-reset` 又报 `NRST is not connected`。
- **解决**：不需要 NRST。用 CubeProgrammer `mode=HOTPLUG` + `-halt` 暂停主控后照常擦写（HOTPLUG 不是只读）；或按住板载实体复位键期间 SWD 可直接附着。

### 1.3 强杀读取导致 ST-LINK 通信雪崩
- **现象**：读完整 Flash 时外部超时（25s）中断工具，之后 ST-LINK 所有事务超时。
- **解决**：给足时间让读取自己完成。读 512KB 需要约 1 分钟。

### 1.4 "Flash memory is write protected (0x20)"
- **现象**：st-flash 写入时报写保护。
- **根因**：USB 超时把 flash loader 的执行搅乱后的副产物——擦除同一批扇区是成功的，说明扇区本身没有写保护。
- **解决**：先解决 USB 链路（1.1），再用 CubeProgrammer `-halt -w ... -v` 流程。

### 1.5 OLED 不亮 ≠ 烧坏了
- **现象**：OLED 全黑，怀疑烧录把芯片搞坏。
- **根因**：读回发现 Flash 前 64KB 全 FF、无启动向量——与更早的备份逐字节一致，即"程序空缺"早就存在。
- **解决**：先独立读回 Flash 判断芯片状态，再下结论。空片反而最好烧。

### 1.6 烧录闭环的标准
- 工具 `-v` 校验通过 ≠ 完成。必须独立读回（`-u 0x08000000 <size>`）+ `cmp` 逐字节比对，再软复位运行看现象。
- **读回长度用实际 bin 大小**（`stat -c %s` 取）——版本迭代后长度会变，用旧长度会假报 EOF 差异。

### 1.7 完整流程速查
`lsusb -d 0483:3748` 确认识别 → 低速（100kHz）HOTPLUG 连接 → 短读取确认 → 全片备份 → `-halt` 写入 `-v` → 独立读回 cmp → `reset=SWrst -rst -run`。

## 2. 硬件与引脚

### 2.1 main.h 的 PD8 注释误导
- **现象**：查 SLP 引脚时 main.h 与文档疑似说 MOTOR_LR_SLP 在 PD8。
- **根因**：LQFP100 封装上 PD8 是 USART3 残留脚位；实际接的是 **PA8**。
- **解决**：以 `main.h:136-137` 与实板为准（PA8）；.ioc 已按 PA8 同步。查引脚一律以 main.h 宏 + 实测为准，不以历史文档为准。

### 2.2 .ioc 与代码的引脚漂移
- **现象**：代码手动初始化了 4 个 SLP 引脚，.ioc 里没有（PB14 还挂着旧板标签 RGB_B）。
- **风险**：CubeMX 重新生成代码会丢掉未登记的配置。
- **解决**：把 SLP 引脚补进 .ioc（2026-11-01，commit dac8a77）。改 .ioc 后重新生成代码要复核（PB14 会新增一条良性重复宏，RGB_B 宏消失）。

### 2.3 电池电压 ≠ MCU VDD
- **现象**：早期把 VREFINT 测出的 3.3V 当电池电压显示。
- **解决**：两者彻底分离（power_monitor 的 vdd/battery 两套字段）；电池走 PB0/ADC1_IN8 分压，换算未配置前显示"电池未配置"，绝不显示 VDD 冒充电池电压。

### 2.4 只写 CCR 不启动 PWM 通道 = 无波形
- **现象**：移交电机后推摇杆完全没反应，寄存器值却是对的。
- **根因**：UI 自检收尾时 `HAL_TIM_PWM_Stop` 关了四路，接管方只 `__HAL_TIM_SET_COMPARE` 不 `HAL_TIM_PWM_Start`。
- **解决**：唤醒分支里同时启动通道。主机测试里必须断言"通道已启动"（CCER 位）而不只是 CCR 值。

## 3. 固件架构

### 3.1 写零也是写电机
- **现象**：自检期间 Ctrl 任务"只是把命令清零"，自检的正/反向 500ms 动作被截断成 10ms。
- **根因**：双归属时代 UI 持有电机，Ctrl 写零同样是写 CCR/SLP。
- **解决**：电机唯一写入者原则——所有输出（含零）只走 Ctrl 的 `ctrl_apply()`；动作页有显式忙状态，普通驾驶与动作互斥。

### 3.2 故障锁存清不掉（自检命令被 stop_all 吞掉）
- **现象**：重新自检永远全 NO FB，故障锁存无法靠"完整重跑全过"清除。
- **根因**：motor_health 锁存后的 `stop_all` 分支每拍把自检服务的 ±8400 命令清零——服务也被当成了普通驾驶输出。
- **解决**：服务 RUNNING 期间豁免 stop_all 的清零（自检判据独立于普通驾驶监测，spec §9.1/§11.4）。注意豁免只作用于"清零命令"这一个动作，新故障照常锁存。

### 3.3 双任务结构体拷贝撕裂
- **现象**：读者拿到"前半新、后半旧"的快照（如 mode 已变而 pulse 还是旧的）。
- **根因**：`taskENTER_CRITICAL()` 挡不住任务切换（configUSE_PREEMPTION=1），跨多字的拷贝可被切成两半。
- **解决**：seq-lock（写者 seq++奇→拷贝→seq++偶；读者 4 次重试 + 临界区兜底）。两处快照（home 状态、UI 快照）同一模式，禁止裸 volatile 结构体跨任务拷贝。

### 3.4 页面打开 ≠ 驾驶许可
- **现象**：想在主页看数据却直接能开车；或自检没过也能出力。
- **解决**：页面状态与运动许可彻底分开。`drive_permitted = 驾驶页 && 自检通过 && 回中100ms && 无故障 && 无动作`，五项缺一不可；动作页（自检/归位/标定）任何摇杆输入都不产生驾驶命令。

### 3.5 静止判据的分叉
- **现象**：页面显示"可以记录"，Ctrl 却拒绝写参考（或反过来）。
- **根因**：页面用 `home.settled_mask` 判断，但该字段只在归位控制分支里写，MANUAL/BUTTON_HELD 下恒 0；且静止计时只在"收到请求那一拍"从零开始，长按前必然失败。
- **解决**：静止跟踪拆成 `wheel_home_track_manual_still()` 由 Ctrl 每轮喂，页面与写参考共用同一累计量；判据口径与 `wheel_home_record_manual_reference` 完全一致（帧有效+反馈有效+四轴回中+CPR 已知+连续 300ms）。

### 3.6 占空比百分比口径
- **现象**："50%" 一词三义（页面百分比 / 占空比 / 比较值）。
- **基准**：占空比口径。TIM8 ARR=16799 → 1%=168 counts；50%=8400（历史满值）、90%=15120、±5%=±840。换算只有一条链 `pct×168`，改任何一头先对齐 spec。

## 4. 页面与渲染

### 4.1 摇杆中位 128 的非对称行程
- **现象**：满杆前进 8400、满杆后退只有 8325，两端不对称。
- **根因**：中心 128 → 上行有效 112 格、下行 111 格，共用一个系数必然不对称。
- **解决**：正负两侧分别按各自有效行程归一化（over/112 与 over/111），两端都精确到 ±上限。spec §8"两端对称"是逐字要求。

### 4.2 RPM 格式化的 4 位数栈溢出
- **现象**：ASan 报 stack-buffer-overflow。
- **根因**：8 字符域的 OVF 阈值写成了 |rpm|>9999，4 位数 "A+1000rpm"=9 字符+'\0' 写穿 buf[9]。
- **解决**：域宽决定阈值（8 字符 → |rpm|>999 即 OVF）；测试必须含恰越界与恰不越界两端（999/1000）。

### 4.3 倒计时的"假冻结"
- **现象**：手柄失联期间确认页数字停了，重连瞬间自检直接启动（跳过剩余时间）。
- **根因**：坏帧早退分支整体跳过了倒计时块——数字不刷新但时间锚点在走。
- **解决**：冻结逻辑（blocked 标志 + 锚点按剩余回推）提到坏帧早退之前；恢复后从剩余继续。教训：**早退分支会绕过尾部逻辑，状态机里所有"每拍推进"的量必须审视每条早退路径**。

### 4.4 屏幕提示了不存在的功能
- **现象**：输出上限页写着"L1返回"，按 L1 没反应（只能 R1 退）。
- **根因**：L1 边沿 switch 漏了新页面的 case，静默落入 default。
- **解决**：加分支 + 测试。教训：**新增页面时逐键过一遍按键表，屏幕上的每个提示都要有对应实现**。

### 4.5 字模粗细不一致
- **现象**：Noto 阈值化生成的字形偏粗且彼此不一，与原点阵字模混排刺眼。
- **解决**：按原始 17 字模的墨水密度（ink/256 均值 μ）为目标带 [0.85μ,1.15μ] 逐字自动选渲染阈值，71 个新增字形全部收敛到同一密度；`tools/render_preview.py` 出 PNG 上板前目检。字模一律由 `tools/font_convert.py` 生成，禁手改。

### 4.6 顶栏高度约束
- **教训**：仪表盘顶栏只有 12px 高，16×16 汉字放不进去——中文排版前先算每个区域的像素预算（顶栏三段 x0..35/x42..83/x90..125），逐段有断言防重叠。

## 5. 测试与验证

### 5.1 motor_test 只看幅值 → 倒转轮假通过
- **现象**：前转段编码器反着转的轮子自检报 OK。
- **根因**：`motor_test_record` 按绝对值判 MIN_COUNTS。
- **解决**：服务侧加方向核对（前转段净计数须为正、反转段须为负，否则钳 0 必判失败）。判据要覆盖"动了但方向错"，不只"动没动"。

### 5.2 测试自身的断言可能就是错的
- 实例：homing 场景的 `compare[i]` 与轮位映射是 **3−i**（CH4/3/2/1 与 A/B/C/D 反序），恒等映射的测试"通过"其实是没测到；测试场景 2 按了两次 USER，第二次是退出手势，让"记录失败"看起来像 bug。
- **教训**：修测试前先证明断言本身的语义；改行为时审查"既有测试更新是否弱化了保护"（本例 test_record_requires_still 曾被门控架空）。

### 5.3 语义变更后集成测试的接缝
- **现象**：单模块全绿，test_motion.sh 的 ctrl 场景挂了。
- **根因**：模块语义变了（长按记录需 manual_calib_page），freertos 还没喂新字段——接缝回归归接线任务，不回退模块语义。
- **解决**：接口变更时同步盘点"谁消费这个字段/信号"，接线前集成测试允许短暂红，但必须登记归属。

### 5.4 tick 回绕
- 所有毫秒计时一律 `(uint32_t)(now - t0)` 形式；每个模块至少一个"从 UINT32_MAX 附近起跑"的用例。真实吃过亏的路径：导航连移、倒计时、电源节拍。

### 5.5 ASan/UBSan 不是装饰
- 4.2 的栈溢出就是 ASan 实证抓到的（人工审查漏了）。内存类测试全部 `-fsanitize=address,undefined -Werror`，任何新格式化函数先补边界断言。

## 6. 工具与平台

### 6.1 git add -A 在多任务并行时会卷入别人的改动
- **解决**：多实现并行时 git add 一律用显式文件清单；每笔 commit 后 `git status` 确认没有夹带。

### 6.2 GitHub API 中文大请求体间歇 403（Unicorn 页）
- **现象**：POST/PATCH 带 ~1KB 中文 body 时返回 403 HTML，同样内容稍后重试或改用 `\uXXXX` 转义（ensure_ascii）就成功。
- **解决**：API 写操作带中文时用 `json.dumps(..., ensure_ascii=True)`；遇到 403 先原样重试一次。

### 6.3 gh CLI keyring token 失效
- **现象**：`gh api` 403，`gh auth status` 报 keyring token invalid。
- **解决**：`git credential fill` 取 git 推送用的同一 token 直接调 API（/user 200 验证可用）；或用户交互式 `gh auth refresh`。

### 6.4 AI 子代理平台约束（执行经验）
- 实现子代理并发上限 1（第二次启动会挤掉第一个）；后台任务在主机断电/关机时静默消失；前台代理约 600s 不活跃会被杀。
- 对策：全程串行、任务间隙立即派发不空等；中断后先审计工作区残留（未提交半成品往往已接近完成），沿用正确部分再补完；每个任务落盘报告文件，恢复的代理读报告续做。

## 7. 裁决记录（spec 与实现冲突时的处理原则）

- **spec 是绑定权威**，plan 是它的论证。冲突实例：端点对称（spec 赢，旧断言改）、输出上限百分比口径（spec 的占空比口径赢，plan 测试期望改）。
- **每条裁决必须落档**（ledger/plan 文档），写明"若错代价是什么"。本周期共 12 条裁决，全部记录在各 plan 文档与提交历史中。
- 测试弱化审查：行为变更时，既有测试的更新必须证明是"新语义的必然结果"而非"把牙齿拔掉"（实例：静止拒绝用例被页面门控架空，返修补回）。
