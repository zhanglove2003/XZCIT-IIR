# OLED 自检异常与初始朝向引导：补充设计

日期：2026-10-30。交付对象：DeepSeek。状态：设计交接，尚未实现。

本设计补充 `2026-10-30-wheel-angle-home-design.md`，修改开机交互与异常监测；四轮映射、最短归位、SELECT 长按 2000 ms 等规则继续沿用原设计。若涉及开机接管时机，以本设计为准。这里的显示设备指 OLED，按键 USER 是主板按键，SELECT 是手柄按键。

## 1. 已核对的当前行为

- `boot_ui.c::ui_motor_selfcheck()` 已逐轮正反转，并通过 `ui_run_with_feedback()` 判断每个方向是否有至少 32 个净编码器计数；不是无条件显示成功。
- 现有判断只证明有净反馈，不证明电机驱动通信在线、接线正确、转速达标或方向正确。
- 失败轮子在图形中主要表现为留空，原因和具体方向没有保存到正常页面；结束后没有常态命令与运动反馈监测。
- `boot_ui_ready` 当前只在 `ui_main_page()` 设置，Ctrl 任务之前不读取手柄。
- `drive_calibration_mode=1` 当前会让 Ctrl 跳过 PS2 读取。因此不能简单打开它，然后等待手柄 SELECT；必须新增能读按键但不能驱动的引导阶段。
- 自检正反转是固定时长，不能假设结束后恰好回到原始朝向。重启又没有有效角度参考，因此禁止直接显示“已回初始位”。

## 2. 用户要求的页面流程

```text
上电等待 USER
  → USER 启动既有自检
  → 所有驱动停止
  → OLED 逐轮自检结果 + 5 秒选择窗口
       ├─ 5 秒内再次按下 USER → 手动初始位页面
       │     → 用户手动对齐四个轮子
       │     → 停稳后长按手柄 SELECT 2 秒
       │     → 记录四轮当前朝向 → 显示记录结果 → 主页面
       └─ 5 秒无人操作 → 主页面（未记录参考时显示 NO REF）
```

5 秒窗口结束后不自动转轮归位，不自动把当前角度认作参考点。普通驾驶与“初始朝向未记录”是两件事：自检正常但未记录参考，仍可正常手动驾驶；短按 SELECT 归位无效并提示先记录。

异常时仍展示同一 5 秒入口，便于手动对齐，但记录参考不等于修好电机或通过自检。建议首版故障策略：自检失败/运行中故障锁存后，四轮停止，禁止手动驱动与自动归位，处理故障后重新自检才能解除；不能通过长按 SELECT 或时间结束清除故障。这个策略应在交付说明中明确告知用户。

## 3. 自检结果与提示文案

保留图形可以，但不能只把失败轮子抹掉。每轮持久保存：`NOT_TESTED/PASS/FAIL`、前向有无反馈、后向有无反馈、两段净计数、原因位和测量时间。

| 现场证据 | OLED 标记与含义 |
| --- | --- |
| 两方向均有达到阈值的净反馈 | `A OK`，只代表本次反馈检查通过 |
| 两方向都无足够净反馈 | `B NO FB`，没有运动反馈 |
| 仅一个方向无反馈 | `B FWD ERR` 或 `B REV ERR` |
| 主动跳过电机测试/标定模式 | `SKIP`，不能显示 OK |
| 采样无效/超出可靠计数条件 | `ENC ERR`，不能猜计数 |

目前是 PWM/DIR/SLP 和编码器，不存在电机在线报文。不要把 `NO FB` 直接标成“确认离线”。它可能来自掉线、无供电、卡住、驱动异常或编码器故障。保留自检失败结果到主页面和诊断快照；VDD 正常不能覆盖电机失败。

5 秒页建议内容（实际布局需适配现有 128 像素 OLED/字库）：

```text
自检结束 / CHECK END
A OK       B NO FB
C OK       D OK
轮标记已回初始位？
USER：手动对齐  5s
```

“轮标记已回初始位？”是向用户提问，不是机器已判定。5 秒无人操作也不能把答案记为“是”。中文没有现成字形时使用短 ASCII 或补字并验证，不能显示空字或越界。

## 4. 5 秒 USER 窗口细节

- 先保证四路 PWM=0 且 SLP 睡眠，结果页首次显示完成后才记 `window_start`。
- 仅接受 USER 释放后的一次新按下边沿，按键低有效，稳定 30 ms；启动自检的那次长按不能直接落入此页。
- 真实毫秒倒计时，使用无符号差处理 HAL tick 回绕。必须在稳定确认的按下事件时间 `<5000 ms` 时进入手动页；过期按下不能在后台误触发。
- 页面循环每 10–20 ms 处理事件，不使用一条 `osDelay(5000)` 阻塞等待。OLED 刷新只在内容变化或每 100 ms 执行，不抢占高优先级控制。
- 超时进入主页面保留所有异常标记。若 VDD 失败，继续沿用电压故障停机逻辑，不能进入可驱动状态；仍可以展示故障和退出说明。

## 5. 手动初始位页面

进入时四轮 PWM=0、SLP 睡眠，不能用电机自动帮用户对齐；Ctrl 继续采集四轮 CNT、轮询 PS2。建议显示：

```text
手动对齐四轮标记
电机已停 / MOTORS OFF
停稳后长按 SELECT 2s
USER：退出且不记录
```

- 摇杆动作不产生电机输出。用户可以自由慢慢手转四轮，不设置 5 秒校准截止时间。
- 只在手柄有效、SELECT 新按下、四摇杆居中且四轮连续停稳 300 ms 后受理长按；长按确认时再次核对停稳。手动调整中不提前记录参考。
- 长按到 2 秒时为四轮同时保存一次参考，显示 `REF SET`；不清除 UI 的累计净圈数，不转轮，不把机械标记假定为自动识别。
- 长按释放不能触发短按归位；若进入页面时 SELECT 已按住，要求先释放再重新长按。
- SELECT 未满足停稳/手柄无效/参考采样无效：保持停机，显示相应提示，不显示记录成功。
- 用户再次按 USER：退出且本次不记录；若从未记录参考，继续保持 NO REF。
- 手动页内接收器失联保持停机并提示，恢复后要求 SELECT 释放再操作；不能自动保存或转动。
- 成功或退出后，等 SELECT/USER 释放、有效摇杆居中持续 100 ms，才允许普通驾驶（前提是自检/运行故障没有锁存）。
- 若自检已失败，可以保存用户指定的计数参考作为记录，但必须提示 `REF SET / MOTOR ERR`；故障锁存仍禁止任何自动归位或驾驶。修复并重新自检会转动轮子，之后需要重新确认/记录参考。

## 6. 运行期间的动态反馈监测

每 10 ms 在唯一的 Ctrl 电机输出路径中，对照“实际施加的有符号 PWM”和归一化编码器变化，手动驾驶/自动归位均监测。UI 不负责判断也不负责停机。

起始参数待上板验证：实际 PWM 绝对值 >=1200、SLP 已醒、换向等待结束后，给 300 ms 启动宽限。之后按 300 ms 窗口看净计数；绝对净变化不足 64 计数则记该轮 NO FB，并四轮停止、锁存故障。小于阈值的微小 PWM 暂不判断运动失败，不能将其显示成“已确认在线”。

持续同方向命令时，归一化净计数与命令符号相反且幅度 >=64，先经过换向/惯性宽限，再标记 `DIR ERR` 并停止。换向、输出零、睡眠、手动对齐、开机尚未移交控制时不累计失败时间。每次换向重新开始窗口；归位沿用已有 500 ms 无进展和 8000 ms 超时，任一监测报错都走统一停止出口。

保留每轮 `last_test_result` 与 `runtime_fault`，可定位哪个轮子、哪个阶段异常。禁止因为下一帧又有计数就自动清除锁存，禁止故障后继续发送非零命令然后直接跳过该轮。抖动取绝对值累加不能作为运动成功证据，应使用回绕处理后的有符号净变化。

## 7. 控制接管与模块边界

启动阶段建议明确分为 `BOOT_LOCKED/RESULT_WINDOW/MANUAL_REFERENCE/NORMAL/FAULT_LOCKED`。UI 决定页面和阶段请求，Ctrl 在自检结束移交后独占电机输出，返回阶段应答/结果快照。进入可读手柄阶段之前必须完成编码器启动、自检收尾、四轮零输出和电机写权限移交；不能 UI 自检和 Ctrl 同时写 PWM。

不能只复用 `boot_ui_ready` 判断是否读取 PS2：引导页需要读取手柄但绝不允许驱动。将“可以初始化/读取手柄”与“允许普通驾驶”明确分开；保留 boot_ui_ready 对普通驾驶的约束，或统一重构为阶段检查并更新原注释/测试，不能仅提前置位造成抢跑。

`drive_calibration_mode` 继续用于已有维修/调试用途，不用它实现会跳过手柄轮询的新手动页。所有阶段请求与 UI 状态使用小快照/消息传递；不通过无保护的 64 位共享读写传参考。UI 只发记录请求，真正捕获四轮计数和记录参考由 Ctrl 完成，再以应答显示成功。

## 8. 实施顺序与验收

1. 增强自检逐轮结果，保持现有约 5.6 秒电机流程和真实计数检查，增加 FAIL 原因/跳过状态，不先延长动作。
2. 增加启动阶段与零输出互斥，支持引导页 PS2 读取；再接入 5 秒 USER 窗口和手动页。
3. 接入原最短归位模块的记录参考请求，按确认应答显示结果，保留全部长短按/取消规则。
4. 实现运行反馈监测与锁存停机，统一故障出口；不得复制一套与归位相互覆盖的 PWM 写入逻辑。
5. 主机测试覆盖正常/缺反馈/单向故障/跳过、故障保留、5 秒边界与 tick 回绕、USER 初始长按不误入、SELECT 释放不误触发、手动页无论摇杆怎样都零输出、无效参考不成功、运行缺反馈/反向反馈/换向宽限、故障锁存和重新自检。
6. 回归已有 `bash tools/test_motion.sh`，新增 UI 页面测试用 ASan/UBSan，完成固件构建。现场先断开电机动力或确保悬空，只读核对 USER/SELECT，再由用户配合测试故障提示、手动记录和归位。不能直接以电机故障码代替实测原因。

尚需机械验证的数字应作为参数暴露并记录测试，不在文档里伪称已经通过；首版不得承诺精密机械朝向或真实电机总线离线检测。
