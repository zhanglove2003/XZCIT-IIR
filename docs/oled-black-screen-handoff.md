# OLED 全黑问题交接（求外部排查）

## 根因已定位：实板 OLED 引脚与原交接表不符（2026-10-29）

旧结论中的 PE1/PE0、「PD5/PD6 属于 RS485」以及“已逐针核对”等说法均不适用于当前实板。

用户提供的主板照片清楚显示 OLED 接口为 `G / 3V3 / D7 / D6 / D5 / D4`，按当前模块 `GND / VDD / SCK / SDA / RES / DC` 对应：

| 信号 | 当前实板引脚 | 原代码错误配置 |
|---|---|---|
| SCK | PD7 | PD7 |
| SDA | PD6 | PD4 |
| RES | PD5 | PE1 |
| DC | PD4 | PE0 |

验证过程：模块 RES 原来持续约 0.15 V；SWD 确认 PD5 当时为输入。仅启用 PD5 内部弱上拉后，MCU PD5 回读从低变高，用户同时测到模块 RES 升至 3.1 V，确认了复位线对应关系。

修正 `main.h`、`gpio.c` 和 `.ioc` 后，编译通过，烧录 `Verified OK`；读回 35068 字节与诊断固件完全一致。PD4～PD7 均为推挽输出，PD5 输出/回读均高，用户确认 OLED 已周期性亮白、熄灭。此前 PE1 回读正常不能证明实际 RES 正常。

随后移除 A/B 白屏无限循环及临时探测接口，恢复 SSD1306 正常初始化和 `ui_wait_key()` 页面；完整编译、主机图形测试与启动数学测试通过。正常界面固件烧录校验通过，回读 40580 字节与构建文件一致。

正常显示后另发现汉字字形镜像：把 `OLED_MIRROR_X` 改为 0 会让“等”跑到右边，不能用整屏翻转修正单字镜像。实际原因是 `tools/font_convert.py` 把原始汉字按页解码后仅顺时针旋转，导致左右偏旁颠倒。最终改为矩阵转置，重新生成全部 17 个汉字，保留 `OLED_MIRROR_X=1`、`OLED_MIRROR_Y=1`。新增非对称偏旁方向测试，修复前失败、修复后通过；图形测试、字库测试和完整构建均通过，最终固件烧录 `Verified OK`。

**用户最终目视确认：“字序和字形都正常”。OLED 黑屏与汉字镜像问题已解决，当前为正常等待按键界面。后续电机/电压自检不在本次已验证范围内。**

实板无可供表笔测量的外部 J4 排针。后续只能使用用户确认可接触的模块/接口针脚，或通过 SWD 调试，不能按旧原理图要求测内部接点。

## 最新现场复核（2026-10-29）

- 用户确认：新模块仍始终全黑；修正万用表挡位后，模块 RES 持续约 0.15 V。此前 VCC/SCK/SDA 等读数尚未在正确挡位下重新确认。
- 实板没有可供表笔测量的外部 J4 排针；不得把原理图中的 J4 当作可接触测点，也不要要求用户测内部座子接点或 MCU 引脚。
- 现有 OpenOCD 服务出现 SWD 通信失败，先前缓存的 running/PC 不能作为当前执行证据。重建服务并将适配器速度降至 100 kHz 后，成功连接 STM32F407；ST-LINK 报告目标参考电压 3.239519 V（并非模块 VDD 的实测值）。
- 短暂停核读取：GPIOE MODER=`0x00001005`、OTYPER=`0x00000000`、PUPDR=`0x00000100`、IDR=`0x0000559E`、ODR=`0x00000002`。PE1 为无上下拉的推挽输出，ODR bit1=1、IDR bit1=1；PE0/DC 输出及回读为低。
- 恢复运行后连续三次读取 GPIOE IDR/ODR，均为 `0x0000559E` / `0x00000002`。已恢复 CPU 运行，没有烧录、复位或修改 GPIO 输出。
- 读回 Flash 起始地址 `0x08000000` 的 35084 字节，与当前 `build/hal_f407_mecanum_4motor_src.bin` 逐字节一致。
- 当前代码为 24 秒 A/B 命令探测循环，没有持续拉低 5 秒的测量窗口。
- 当前重点：MCU PE1 数字输入和输出均高，而模块 RES 实测低，两端状态不一致。优先查 PE1 至模块 RES 的连接、接触、实际信号对应和测量参考地；尚不能据此确定是哪一处故障，也不能判定模块损坏。GPIO 回读不等于模块端电压测量。
