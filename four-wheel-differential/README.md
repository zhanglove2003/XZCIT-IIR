# 四轮差速底盘固件（C50C）

本目录是 C50C 四轮差速底盘的完整固件工程，源码为 WHEELTEC 原厂 Diff_Car 结构，保持独立、不与仓库根目录的麦克纳姆工程共用任何代码。

- 目标芯片：STM32F407VET6（FLASH 512K / SRAM 128K）
- 构建系统：GNU Make + `WHEELTEC_C50C.ld`
- 宏：`DIFF_CAR`、`_4WD_CAR`

## 1. 当前状态

- 通过 PS2 手柄控制四轮差速底盘：左摇杆上下控制前进、后退，右摇杆左右控制转向，两轴可混合。
- 当前烧录版本把最大 PWM 命令从 1500 提高到 8400。定时器周期为 16800 个计数，因此满摇杆时最大占空比为 50%。这不代表轮速为最高转速的 50%。
- 该版本已通过串口 1 烧录，写后 128 KiB 区域读回一致，启动命令确认。现场运行与转向正常。
- 这是调试用**开环 PWM 控制**，不是四轮速度闭环，也不是已验证的 ROS 自动导航底盘。

## 2. 车轮、电机与编码器

下文左、右均以车头朝前为准。必须区分三种编号：

1. **电机输出通道**：软件 `MOTOR_A` ~ `MOTOR_D` 及其 PWM 输出。
2. **板上编码器接口丝印**：实物插座 A、B、C、D。
3. **固件编码器通道**：`Encoder_A` ~ `Encoder_D`、定时器及 `g_encoder_diag` 下标。

字母相同不证明三种编号连接到同一个车轮。

### 2.1 电机输出

| 实际车轮 | 软件电机输出 | TIM8 PWM 引脚 | 四轮模式传给 `Set_Pwm()` 的命令 |
| --- | --- | --- | --- |
| 右后 RR | A | CH4 / PC9 | `-right` |
| 左后 RL | B | CH3 / PC8 | `left` |
| 左前 FL | C | CH2 / PC7 | `left` |
| 右前 FR | D | CH1 / PC6 | `-right` |

当前调用为 `Set_Pwm(-right, left, left, -right, 0)`。输出符号包含现有电机方向适配，**不是**编码器方向的证据。

源码位置：`BALANCE/balance_task.c` 的 `ResponseControl()`；PWM 引脚定义见 `HARDWARE/Inc/motor.h`。

### 2.2 板上编码器插座（用户沿线确认）

| 实际车轮 | 板上编码器插座丝印 |
| --- | --- |
| 右后 RR | **B** |
| 左后 RL | **C** |
| 左前 FL | A |
| 右前 FR | D |

前轮 A/D 的线束确认为更早一轮的现场记录；后轮 B/C 曾做断电拔插隔离测试。

### 2.3 固件编码器编号与定时器

下表是**源码定义**，不是对板上丝印与实际车轮电气连通性的证明。

| 固件诊断编号 | 数组下标 | 定时器 | MCU 输入引脚 |
| --- | --- | --- | --- |
| A | `g_encoder_diag[0]` | TIM2 | PA15、PB3 |
| B | `g_encoder_diag[1]` | TIM3 | PA6、PA7 |
| C | `g_encoder_diag[2]` | TIM4 | PB6、PB7 |
| D | `g_encoder_diag[3]` | TIM5 | PA0、PA1 |

定义位置：`HARDWARE/Inc/encoder.h`；读取位置：`HARDWARE/encoder.c` 的 `Read_Encoder()`。定时器编码器模式使用 TI12；诊断记录原始计数和过滤后的计数。

**当前代码基线**：临时后轮里程计使用**固件诊断 B** 作为左轮、**固件诊断 C** 作为右轮，并对右轮取反，见 `BALANCE/data_task.c` 与 `BALANCE/Inc/rear_odom.h`。后续维护以当前代码行为为准。

板上丝印记录为 B = 右后、C = 左后，与上述固件通道名称不同；两套编号的对应关系尚未用隔离测试的原始串口日志独立核实。若要改编码器代码或用于速度闭环、导航，应先在电机驱动电源断开时结合单轮原始计数核实映射、方向和标定。

当前临时换算使用约 **102000 计数/后轮一圈**；该值和方向仍需复测，不能视为最终标定。

## 3. 控制规则与局限

源码：`BALANCE/steer_debug.c`，调用位置：`BALANCE/balance_task.c`。

- 左摇杆 `LY`、右摇杆 `RX` 各有 20 个原始量的死区。
- 初次启动和输入失效恢复后，两轴须同时回中并保持约 100 ms，才允许输出。
- 最大命令 8400；双轴混合后按比例限制左右侧，避免超过上限。
- 左右侧分别处理换向，反向前输出零至少 20 ms。这个软件间隔不等于已验证高转速下的机械换向安全。
- 中位或程序识别到输入无效时，输出归零。有效性条件含 PS2 模式、控制状态和最近 150 ms 内的有效帧。
- PS2 接收器如果在失联后持续重复非零旧帧，现有逻辑不能保证识别断连。**不能将此固件描述为已完成失联保护验证。**
- 输出为开环 PWM，轮速、实际方向、负载、电机电流及底盘运动还受机械与供电影响。

## 4. OLED 与串口

- OLED 调试页面只显示后轮 `RL`、`RR`，显示各侧 PWM 百分比和临时速度；前轮不在该页面显示。
- **串口 1**：应用波特率 115200、8N1；当前编译开启 `ENCODER_DIAG`，输出 `ENC_DIAG` 文本诊断。该接口也用于 ROM 下载，打开串口、改变 DTR/RTS 可能使板子复位或进入下载模式。
- **串口 3**：115200、8N1，发送 24 字节二进制状态帧，可用 `tools/c50c_uart3_monitor.py` 解码，不是普通文本日志。监视程序与 ROS 节点不要同时占用同一设备。
- 串口 3 保留厂商串口命令解析代码，但当前 `FOUR_TURN_DEBUG` 输出分支要求 PS2 控制模式，**不应声称 ROS 2 速度控制已实现或已验证**。DMA 收发优化尚未移植。

## 6. 烧录与恢复

- 工具：`tools/c50c_uart1_flash.py`，串口 1、57600 波特率，快速基线模式。
- 串口打开、复位、烧录和电机启动前，应说明操作并取得授权。烧录前确认电机驱动电源断开，C50C 与串口仍供电。
- 115200 曾完成下载但也有握手失败；230400 曾出现启动命令握手失败。57600 是近期完整烧录、校验和启动流程成功使用的速度。
- 若基线不匹配、擦写范围变化或无法确认板上版本，不要强行沿用旧基线。

## 7. 下一步现场核验

1. 修改固件后，先稳固架空车身、四轮离地，备好断电方式，再从小幅输入开始复测。
2. 断开电机驱动电源，复核前轮编码器插座及 B/C 丝印与固件 `g_encoder_diag`/TIM 通道的关系。先确认原始计数与实际单轮转动一致，再校准方向与每圈计数。
3. 完成速度与里程计验证后，再讨论 ROS 2 协议、速度闭环及串口 DMA。**不得把当前临时后轮诊断当作已验收的导航里程计。**
