## 3. 许可仲裁新语义（11-23 起，改过 arbitration 必读）

`safety.rs::license_accept` 的会话裁决新增**登录顶替凭证**：

- `manual_login` 成功 → `ctl.manual.login_takeover_at = Some(now)`（一次性凭证，10s 窗口）。
- 窗口内第一帧带**新会话号**的 `motion_license` 心跳 → 立即 `Takeover`（不等旧会话 350ms 断流），消费凭证（归 None）。
- **安全语义不变**：Takeover 仍先 `lock_locked("license_lost")` 锁停一次（下游 guard 看到会话变化也会 `_latch` 要求显式 rearm）——顶替 ≠ 免锁停，顶替后必须点「恢复」才能动车。
- 凭证按「登录后下一帧」发放：许可帧来自 Worker 独立连接、不携带登录身份，无法绑定连接号；凭证发放必经登录，匿名页抢不到。
- 旧页此后收 `session_mismatch` nak，Worker 持续重发被拒即静默降级（`ui.lic.state='session_mismatch'`，判读条「许可异常 会话被占用」）。
- 窗口判定提为 `Hub::login_takeover_active(ctl, now)` 便于测试（测试进程启动 <10s 时 `saturating_sub` 钳 0 会让"过期"造不出来，别直接拨时刻，用注入 now 的单测）。
- 单测：`test_login_takeover_immediate_and_one_shot`、`test_login_takeover_window_expiry`（cargo test 37 全过）。

**用户操作语义**：换页面/换设备控车 = 新页面登录即可，不用再等旧页关闭；但每次顶替后判读条会出现「已锁停 许可中断」，点一次「恢复」即可。**「一切正常但车不动」优先查判读条锁停项**（11-23 实测：锁停拦手动，服务端回「已锁停，请先点恢复」，不是静默丢弃）。

## 4. 新坑（续旧档 §7 编号）

20. **开发机 git 推送代理坑**：`~/.gitconfig` 给 github.com 配的代理 `127.0.0.1:7897` 是死的（活代理是 7890），裸 `git push` 必撞 `Failed to connect to 127.0.0.1:7897`。推送用单次覆盖（不改全局配置）：
    ```bash
    git -c http.https://github.com/.proxy=http://127.0.0.1:7890 -c http.proxy=http://127.0.0.1:7890 push origin feat/ui-polish
    ```
    直连（清代理）会 TLS 握手中途被掐（GnuTLS -110），GitHub 走代理是稳的。7897 代理哪天复活了可以改回全局。
21. **无头 CDP 验证三坑**（magpie MCP 掉线时用 `google-chrome --headless=new --remote-debugging-port=9222` + node 脚本驱真板）：(a) `PUT /json/new` 建的 tab 不导航，页面跳转必须 `Page.navigate` + 等 2s；(b) CDP 回包解包是 `r.result.result.value`（少一层得 undefined，先 RAW dump 校深度）；(c) 登录要发 `manual_login` WS 帧或表单 submit 事件——合成 `btn.click()` 不触发 form submit。页面侧读许可状态用 `C50C.Store.state.ui.lic.state`（`C50C.ui` 不存在，别猜）。
22. **es8388「音量对但无声」第二开关**：`Headphone Switch`（numid=33，iface=MIXER）**无法用简单控件名查询**（`amixer -c 2 sset 'Headphone Switch' on` 报找不到），只能 `amixer -c 2 cset numid=33 on`。它曾以 off 固化在 `/var/lib/alsa/asound.state`（11-06 的旧值），每次开机恢复成静音。改完必须 `sudo alsactl store 2`（sudo 密码 `xzcit-opi`）固化，`alsa-state` 守护只在关机时写盘。排查顺序：numid=33 开关 → PCM raw 值/dB（26%=−71dB 不可闻）→ aplay 通路。
23. **RMW 混跑：垫片单独切 Cyclone = 服务调用静默挂死**（旧档未录，11-23 实锤）。整车栈全 FastDDS；11-22 19:47 有人给 `c50c-web-bridge.service` 单独插 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`（A/B 试验），**话题**（/map /scan /image）跨厂商 RTPS 互操作全正常，唯独**服务调用**（list_parameters、lifecycle）静默挂死 → 垫片「参数探测超时 10s」循环、概览底盘常挂离线。诊断口诀：**`ros2 param list /c50c_uart3_node`（FastDDS CLI）秒回而垫片探测超时 = RMW 混跑嫌疑**。11-23 08:49 已回退 FastDDS（Cyclone 版备份 `.bak-cyclone`），2 秒恢复。真解 = 全线统一 RMW（REPORT_20261122_localization.md §5.3，定位工作流 A–D 延后项）；若重试 Cyclone 必须整栈同切，绝不单进程混跑。代价：坑 19（FastDDS 下 rclpy context ~2min 坏死）会复发，靠垫片双看门狗自愈（周期性数秒断流是正常现象）。
24. **「重启相机/雷达」按钮杀整组传感栈（已修）**：按钮 = `systemctl --user restart opi-robot.service`（ExecStart=start_web.sh，Type=oneshot+RemainAfterExit）。脚本末行 `systemctl --user start c50c-web-watchdog.timer` 指向**掩码单元**（旧档 §4 的 mask 操作留下的 → /dev/null 软链）→ start 必非零退出 → systemd 判 unit failed → KillMode=control-group 把**刚拉起的**相机/雷达/TF/融合整组 SIGTERM（实测相机起来 4 秒后全灭）。**修复**：脚本末尾追加 `exit 0`（注释 N3 2026-11-23，备份 `.bak-noexit`）。修复后 unit Result=success，点按钮 12s 后四节点全在线。**注意**：mask 仍然是对的（防止旧 web_debug 抢 8088），exit 0 只是让 oneshot 正常收尾，两者不冲突。
25. **手工拉起仪式**（start_web.sh 出问题时兜底，照抄 dds_watchdog.sh recover()）：精确 pkill（模式写 `xxx[.]py` 防命中 ssh 远程 shell 自杀）后 `cd /home/orangepi && SLAM_MODE=nav setsid bash start_web.sh`——必须 SLAM_MODE=nav（否则 slam_toolbox 与 AMCL 抢 map→odom）、必须 setsid（裸 nohup 会被 ssh 会话退出带走）。ssh `pkill -f` 自杀教训：命令行里含同串即命中自己（exit 255）。
